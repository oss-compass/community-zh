## 会议纪要
### 一、Agent 上下文压缩与跨阶段摘要优化（朱家顺、齐国强）
针对 Agent 在复杂任务执行中的上下文管理问题，会议重点讨论了压缩效果与跨阶段信息传递的准确性：

**1. 压缩机制与效果验证**

- 双层压缩策略确认：朱家顺展示了双层压缩的实现效果，其中单步压缩用于保留关键提示信息，而整体压缩则大幅减少了上下文长度（如从 15 万 Token 压缩至 8 万 Token）。
- 摘要可视化要求：齐国强强调需在 HTML 或 JSON 报告中直观展示压缩前后的具体内容对比，以便于评估压缩策略的有效性。

**2. 跨阶段摘要的版本冲突排查**

- 环境版本不一致问题：在 ops-math 项目中，Agent 在 Setup 阶段使用了 8.5.2 版本，但在 Quick Start 阶段因硬编码问题导致失败，需使用 9.2.0 版本才能成功。

- 职责边界与信息传递：齐国强指出该问题属于 Agent 任务规划或文档同步问题，而非摘要逻辑缺陷。要求确保 S1阶段的环境探针信息能准确传递给 S2阶段，以维持多环境下的一致性。

**3. 环境信息标准化**
  通用 Prompt 规范：齐国强建议构建通用的环境描述 Schema，涵盖硬件（驱动、固件）与软件（OS 版本、内核、关键库版本）的标准化信息，以提升 Agent 对环境的感知能力。

### 二、Issue 指标评估体系优化（李升保、代睿祺、齐国强、王晔晖）
针对 Issue 处理质量的评估模型，会议对评分标准进行了细化，并解决了指标间的边界混淆问题：

**1. 回复质量与责任明确度的剥离**

- 指标边界修正：针对“首次回复质量”评分中混入“责任明确度”维度的问题，齐国强与王晔晖达成共识，要求将两者隔离。回复质量仅关注信息量（如确认问题、给出结论、提供计划），不考察责任人（Assignee）字段。
- 高分回复标准：明确了满分回复应包含“确认问题有效性”、“给出初步结论/状态”以及“提供具体排查计划或时间线”，而非泛泛的“尽快评估”。

**2. 评估模型优化与验证**
  - 异常操作识别：针对短时间内（如几秒内）重复 Assign 的手误操作，代睿祺提出需在模型中增加识别逻辑，但目前模型尚未挖掘到该层次，需进一步调优。
  - 验证进度与目标：李升保正在基于最新指标跑分，目前完成度约 60%-70%。王晔晖要求在下周一正式上线前，完成对 8 月份低分 Issue 的全面排查，并将验证完成度提升至 80%。

**3. 协同评审机制**

  - 第三方专家 Review：为确保指标评估的客观性，王晔晖建议李升保可以将过程中的报告同步给代睿祺，由代睿祺作为第三方专家进行 Review，重点关注已完成的指标项。

### 三、待办
- 将已跑好的 html 与代码路径发给齐国强评估，并行多跑几个项目。（负责人：朱家顺；完成时间：2026年8月25前） 
- 调整 Issue 指标评估模型，修正“回复质量”与“责任明确度”的边界，剔除责任人维度的干扰。（负责人：李升保；完成时间：2026年8月25前）

### 一、OSS-Compass 指数接入（王晔晖、张盛翔）

王晔晖提出当前有一件事需推进：OSS-Compass指数接入Gitee。指数接入涉及 V2 到 V3 版本更新及数据刷新，主要取决于张盛翔侧的启动及挂件更新；张盛翔反馈本周与相关人员沟通后，受资源投入所限时间窗口不会太快。双方确认：数据爬取可先行、不阻断，待挂件更新完成后即可同步推进接入。

### 二、Agent 上下文压缩方案进展与调优（朱家顺、齐国强）

朱家顺汇报了上下文压缩工作的可视化进展与效果，齐国强对摘要质量提出多项调优建议。主要内容包括：

- 触发机制：两种——单步超长触发（如单步超过 2 万 token）与跨阶段摘要触发（每个大阶段结束后固定一次摘要传入下一阶段）。
- 压缩效果：典型单步压缩比约 50%，但当前尾部信息保留过长、冗余较多，头尾比例与精炼度不足。
- 跨阶段摘要语义问题：齐国强指出摘要中"错误""痛点"等字段语义混乱、与前面信息重复，需规范化为"任务执行结果、执行的命令与返回"；痛点不应跨任务携带，仅作为最终结果。
- 提示词调优方向：齐国强建议压缩应"去重"而非简单摘要，保留头尾关键信息与报错、环境信息，去除常规冗余日志；可参考 cloud code 的纯提示词摘要方案，摘要应包含当前环境、历史执行指令与结果概述、关键文档与代码片段等内容。
- 环境信息保留：每个任务中标准基础信息（硬件系统环境、历史安装库、环境变量等）应保留并可在任务间共享，建议通过摘要引导模型生成而非代码固定占位符填充。
- 全局背景信息：齐国强建议暂不引入复杂的全局任务背景维度，统一在摘要中以通用维度（环境、历史工具与结果、关键信息点）保留，任务特异配置不在此体现。

### 三、Issue 评分方案设计（代睿祺、王晔晖）

代睿祺介绍了更简洁的 Issue 评分设计思路：将 i0 阶段作为背景知识进行评分，其余三部分分别为"首轮分配与首次响应讨论""推进""总结关闭"，统一以"质量"和"效率"两个维度作为北极星指标，其下细化支撑指标；不同 Issue 类型（bug、需求、咨询类）在各阶段的两维度阈值与关注幅度会有差异，但均在质量与效率范围内适用。王晔晖表示可继续沿此思路推进，次日进一步对齐。

### 四、待办 

**1. Agent 上下文压缩优化**

- 优化上下文压缩的 Prompt，增加全局任务背景，并调整摘要逻辑以提升语义清晰度。（负责人：朱家顺；完成时间：2026年8月18前）
- 多跑几个项目，将效果链接发给齐国强评估。（负责人：朱家顺；完成时间：2026年8月18前）

**2. Issue 评分方案**

- 继续细化基于质量与效率双维度的 Issue 处理评估框架，并针对不同 Issue 类型制定差异化指标。（负责人：代睿祺；完成时间：2026年8月18前）
